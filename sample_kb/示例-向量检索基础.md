# 示例笔记：向量检索基础

> 本文件是仓库自带的示例文档，内容为公开常识，仅用于演示上传与检索，不包含任何个人资料。

## 向量是索引，不是答案

文本经过 Embedding 模型会变成一串固定长度的数字（例如 768 维）。
向量数据库拿问题的向量和库里的向量比对相似度，**返回的是向量所指向的那条记录**，
也就是原文、来源文件和页码，而不是向量本身。

可以类比 MySQL：走 B+ 树索引查询时，返回的是数据行，没人期望它返回索引节点。

## 为什么要切块

整个文件压成一个向量会丢掉所有细节，而且无法定位到具体页码。
所以入库时要先把长文切成小块，每块单独算一个向量。

常见切分参数：

- 块大小 300–500 字
- 相邻块重叠 10%–15%，避免一句完整的话被切断
- 优先在段落、句号等自然边界断开

## 相似度与距离

余弦距离越小表示越相似，为了直观通常换算成相似度：

```
similarity = 1 - distance
```

这样数值越大表示越相关，便于设置过滤阈值。

## 什么不适合放进向量库

精确匹配类的数据不适合用向量检索。例如订单号、工单号这类标识符，
不同记录的文本结构高度相似，向量几乎无法区分，应该用数据库的精确查询。
