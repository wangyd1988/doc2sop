# 单机 Docker 服务日常巡检规范

适用于用 Docker 部署在单台云服务器上的小型服务。每天上班后执行一次，约 3 分钟。
巡检只看不改：发现异常先记录，再按对应的排障手册处理。

## 巡检步骤

### 1. 宿主机磁盘

查看各挂载点使用率。

- 根分区使用率超过 80% 记为告警，超过 90% 记为严重。
- Docker 数据目录所在分区满了以后，容器写日志会失败，镜像也拉不下来。

### 2. 宿主机内存

查看剩余内存与 swap。

- 可用内存低于总量 15% 记为告警。
- swap 使用量持续增长，说明内存长期不够，需要评估扩容或给容器设上限。

### 3. 开机时长与负载

查看开机时长和 1/5/15 分钟平均负载。

- 开机时长明显短于预期（例如只有几小时），说明机器夜间发生过重启，要追查原因。
- 15 分钟负载持续高于 CPU 核数，记为告警。

### 4. 容器运行状态

列出所有容器，确认该运行的都在运行。

- 状态不是 running 的业务容器，记为严重。
- 状态里出现 Restarting，说明容器在反复重启。

### 5. 容器资源占用

查看各容器的 CPU 与内存占用。

- 内存占用超过其上限的 80%，记为告警，存在被 OOM 杀掉的风险。

## 巡检结论格式

按「正常 / 告警 / 严重」三级给出每一项的结论，最后汇总需要跟进的事项。
