# 大模型网关使用说明

公司统一通过大模型网关（基于 LiteLLM）对外提供模型能力。所有同事都用自己的 key 调用，
不要把 key 写进代码仓库或发到群里。

## 怎么调用

网关兼容 OpenAI 接口。把 SDK 的 `base_url` 指向网关地址，`api_key` 填自己的 key 即可。
模型名必须使用网关里登记的名字，例如 `bai/deepseek-v4-flash`，不能直接写厂商原始模型名。

## 额度与限制

- 每把 key 可以设置预算上限（max_budget）和预算周期（budget_duration），超出后会被拒绝，周期到了自动重置。
- 每把 key 可以限制每分钟请求数（rpm_limit）和每分钟 token 数（tpm_limit）。
- 每把 key 只能调用授权给它的模型；没有授权的模型会返回「无权访问」。
- key 可以设置到期时间（expires），过期后不可用。

## 调不通时的自查步骤

遇到报错，先按下面的顺序自查，大部分问题不需要找管理员：

1. **先看网关本身是否健康。** 如果网关状态不是 healthy，或者数据库没连上，是网关故障，
   所有人都调不通，直接联系管理员，不用往下查了。
2. **再看这把 key 能用哪些模型。** 报「模型不存在」或「无权访问该模型」时，
   核对你代码里写的模型名是否在可用列表中，注意大小写和前缀都要完全一致。
3. **最后看 key 的额度和限制。**
   - 已花费（spend）达到预算上限（max_budget），会被拒绝，等预算周期重置或申请提额；
   - 报 429，多半是触发了 rpm_limit 或 tpm_limit，降低并发或申请调高；
   - key 已过期（expires 早于今天）或被封禁（blocked），需要重新申请。

## 常见报错对照

| 报错 | 常见原因 | 先查哪一步 |
|---|---|---|
| 401 Unauthorized | key 写错、过期或被封禁 | 第 3 步 |
| 403 / 无权访问该模型 | 模型未授权给这把 key | 第 2 步 |
| 404 / 模型不存在 | 模型名写错 | 第 2 步 |
| 429 Too Many Requests | 触发限流 | 第 3 步 |
| 400 Budget exceeded | 预算用完 | 第 3 步 |
| 502 / 503 | 网关或上游模型故障 | 第 1 步 |

## 申请与提额

新 key、新增模型权限、调整预算或限流，在内部工单系统提交「模型网关」类工单，注明用途和预计用量。
