# 模型服务自查手册（示例）

本手册为示例文档，用于演示，内容不代表任何真实公司的规定。适用于直接调用模型服务商
（如硅基流动、DeepSeek）或公司统一网关的同事。

## 一、怎么调用

- 所有服务都兼容 OpenAI 接口：SDK 的 `base_url` 填服务商地址（以 `/v1` 结尾），`api_key` 填自己的 key。
- **key 是个人凭据**，放在环境变量里，不要写进代码仓库，也不要发到群里。
- **模型名必须和服务商「可用模型列表」里登记的完全一致**，包括组织前缀和大小写，
  例如 `deepseek-ai/DeepSeek-V4-Flash`，不能只写 `deepseek` 或 `DeepSeek-V4-Flash`。

## 二、调不通时的自查步骤

遇到报错，先按下面的顺序自查，大部分问题不需要找管理员：

1. **先看这把 key 能用哪些模型。** 用自己的 key 调一次模型列表接口。
   报「模型不存在」「无权访问该模型」时，核对代码里写的模型名是否出现在列表里；
   不在，就是名字写错或该模型没有开放给你。能正常列出模型，也说明 key 本身是好的。
2. **再看账户状态与余额。** 查账户信息接口（硅基流动是 `/v1/user/info`）：
   - `status` 不是 `normal`：账号被限制，联系管理员；
   - `totalBalance` 为 0 或接近 0：余额不足，充值或申请预算。`balance` 是赠送余额，
     `chargeBalance` 是充值余额，扣费先扣赠送、再扣充值。
3. **最后看是不是限流。** 报 429 多半是每分钟请求数（RPM）或每分钟 token 数（TPM）超限：
   降低并发、加重试退避，或向服务商申请调高限额。

## 三、常见报错对照

| 报错 | 常见原因 | 先查哪一步 |
|---|---|---|
| 401 Unauthorized / Invalid token | key 写错、已删除或过期 | 第 1 步 |
| 403 / 无权访问该模型 | 模型未开放给这把 key | 第 1 步 |
| 404 / 模型不存在 | 模型名写错 | 第 1 步 |
| 余额不足 / Insufficient balance | 账户余额为 0 | 第 2 步 |
| 429 Too Many Requests | 触发 RPM / TPM 限流 | 第 3 步 |
| 503 / Model service overloaded | 服务商侧过载 | 稍后重试，或换同类模型 |

## 四、新同事开通

- 自行到服务商控制台注册并创建 key，首次充值后再用于正式任务；
- 走公司统一网关（LiteLLM）的同事，按《大模型网关使用说明》提工单申请 key 与模型权限。
