# 评测集

把「这套系统效果怎么样」变成可复现的数字，而不是凭感觉。

## 数据格式

`dataset.jsonl`，一行一条，当前 5 条是配合 `sample_kb/` 的示例，**待补充到 20 条**。

| 字段 | 说明 |
|---|---|
| `id` | 唯一编号 |
| `question` | 提问原文 |
| `expected_points` | 答案里应当出现的关键信息点（人工列出） |
| `expected_sources` | 期望命中的来源文件名；空数组表示"知识库里本就没有" |
| `type` | `fact` 事实查询 / `concept` 概念解释 / `multi_hop` 跨文档 / `refusal` 应当拒答 |

## 为什么要有 `refusal` 类型

RAG 最危险的失败不是答不出，而是**知识库里没有却编造一个**。
拒答类问题专门用来验证这一点，建议占 20% 左右。

## 建议的指标

| 指标 | 怎么算 | 看什么 |
|---|---|---|
| 召回命中率 | `expected_sources` 是否出现在检索结果里 | 检索环节是否可靠 |
| 要点覆盖率 | `expected_points` 被答案覆盖的比例 | 生成环节是否完整 |
| 拒答正确率 | `refusal` 类问题是否正确拒答 | 是否会编造 |
| P50 / P95 延迟 | 端到端耗时 | 体验是否可接受 |

**先拆开看检索和生成。** 如果召回命中率低，调切分和 `TOP_K` 没用，要先解决检索；
如果召回正常但要点覆盖率低，问题在提示词或模型。
