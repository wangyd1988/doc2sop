# 五分钟演示：一条命令跑起「小知」，看到工具 + SOP 的效果

这份文档是「照着做一定能复现」的步骤表，也是录演示 GIF 的脚本：精确到点哪里、问什么、预期看到什么。
全程不需要 k8s、docker socket 或自托管模型——只要 Docker 和一把模型 key。

## 0. 准备（2 分钟）

| 需要 | 说明 |
|---|---|
| Docker | Docker Desktop（Windows / macOS）或 Docker Engine + Compose v2（Linux）；2 核 2 GB 的小主机够用 |
| 一把硅基流动 API key | 到 [cloud.siliconflow.cn](https://cloud.siliconflow.cn) 注册 → 「API 密钥」→ 新建。推荐它的原因只有一个：**同一把 key 同时提供对话模型和向量模型**（`BAAI/bge-m3`），不用再找第二家 |

别家也行（DeepSeek、百炼、任何 OpenAI 兼容地址 + 一个向量模型地址），见 README「进阶：正式部署」。
只是演示二里「账户余额」那个工具查的是硅基流动的接口，换厂商会返回 404——Agent 会如实说明，不影响其他部分。

## 1. 启动（1 条命令）

```bash
git clone https://github.com/wangyd1988/personal-kb.git && cd personal-kb
cp .env.example .env
# 用任意编辑器改两处：WEB_PASSWORD（登录密码）、LLM_API_KEY（刚申请的 key）。
# 建议顺手把 OPS_TOKEN 也换成一串随机字符。文件必须保持 LF 换行、无 BOM。
docker compose up -d --build
```

`.env.example` 里预置了 `COMPOSE_PROFILES=demo`，所以这条 `up` 等价于 `docker compose --profile demo up -d --build`，
会起两个容器：

| 容器 | 干什么 | 内存上限 |
|---|---|---|
| `kb-app` | 知识库应用，监听 `127.0.0.1:8765` | 900 MB |
| `kb-ops` | 只读工具 sidecar：跑 `deploy/ops_readonly.py`，工具定义来自 `packs/` 里的两个场景包；端口不对外发布 | 128 MB |

首次构建要下载 Python 依赖，视网络 1–3 分钟。然后核对：

```bash
docker compose ps                 # 两个容器都 running / healthy
docker compose logs kb-ops        # 看到「可用工具 4 个：date_info, gateway_balance, gateway_models, holiday_calendar」
```

> 用户在这一步做的事：改 2 个值 + 敲 1 条命令。

## 2. 登录，等场景包自动就位（约 30 秒）

打开 http://127.0.0.1:8765 ，用户名 `admin`，密码是 `.env` 里的 `WEB_PASSWORD`。

欢迎页的引导卡会先显示：

> ⏳ 正在导入演示场景包「leave-planning」：休假管理制度.md：向量化 2 个片段

这是应用在后台把 `packs/leave-planning` 和 `packs/model-selfcheck` 两个场景包导进来：文档入库、随包附带的 SOP 直接加载
（不用现场抽取）。几十秒后引导卡变成：

> ✓ 已有 2 个文档　✓ 已有 1 个 SOP 生效，4 个工具可用　3 问一句

欢迎页下方的示例问题也换成了场景包里的（点一下就发送）。

想看细节：顶栏「管理」→「工具」能看到 4 个工具的命令 / 接口地址（key 不可见）；「SOP」里《休假管理制度.md》分组下有
《请假拼假核对》，每一步后面引着文档原句。

## 3. 演示一：照着 SOP 办事（行政 · 请假拼假）

**点**欢迎页第一个示例问题，或在输入框输入：

> 2026 年国庆想连休到 10 月 11 日要请几天年假

**预期看到**（措辞每次略有不同，要点不变）：

1. 回答上方出现两张工具调用卡片：🔧 `holiday_calendar`（year=2026）、🔧 `date_info`（2026-10-08 等，可能调用多次）。点开能看到原始返回。
2. 回答第一行：**「按 SOP《请假拼假核对》执行」**，然后是一张「步骤 | 查看 | 实际数据 | 结论」表：
   - 第 1 步 · 2026 年法定节假日安排 → 国庆节 10 月 1 日–7 日放假；**10 月 10 日（周六）补班**
   - 第 2 步 · 10 月 8 日–11 日各是星期几 → 10/8 周四、10/9 周五、10/10 周六（补班日，算工作日）、10/11 周日
3. 结论：**请 3 天年假（10 月 8 日、9 日、10 日），可从 10 月 1 日连休到 10 月 11 日共 11 天。**
   并引用《休假管理制度》：补班日虽在周末也计入请假天数；与法定节假日连休需至少提前 10 个工作日申请，3 天以内由部门负责人审批。

这一问的价值在「补班日」这个坑：凭直觉会答 2 天，按 SOP 一查数据就是 3 天。

## 4. 演示二：SOP 从实践里长出来（研发 · 模型调用自查）

研发场景包**故意没有带 SOP**，这一段演示它怎么长出来。

**问**（点「新对话」后输入，或点示例问题）：

> 我这把 key 能用哪些模型？余额还剩多少？

**预期看到**：

1. 两张工具卡片：🔧 `gateway_models`、🔧 `gateway_balance`。
2. 回答列出这把 key 能调用的对话模型（硅基流动会返回几十个，Agent 会归纳），以及账户状态与余额；
   对照《模型服务自查手册》说明「模型名要和列表完全一致」「余额为 0 会被拒绝」。
3. **回答结束后 5–30 秒**（后台让模型整理轨迹），回答下方出现一张 💡 卡片：

   > 💡 这次用 2 个工具、2 步得出结论，沉淀为 SOP《模型调用自查》？
   > 适用：…　[查看步骤]　**保存**　忽略

   「查看步骤」能展开：`gateway_models` → `gateway_balance`，每步有检查点，依据写着「第 1 次调用 gateway_models 的返回：…」。
4. **点「保存」** → 卡片变成「✅ 已保存到 SOP《模型调用自查》（默认停用，去 SOP 页核对后启用）」。
5. **点顶栏「SOP」**，在「从实践沉淀」分组里找到它，**点「已停用」**把它切成「已启用」（这就是「人确认」那一步）。
6. **再问一遍同类问题**（新对话）：

   > 帮新同事看看他的 key 能用什么模型、余额够不够

   这次回答第一行是 **「按 SOP《模型调用自查》执行」**——上一轮的自由排查，已经变成团队的标准做法。

SOP 名字由模型起，可能叫《模型调用自查》也可能叫《模型 key 可用性与余额核对》；都对。

## 5. 收尾

```bash
docker compose down          # 停掉，保留 ./data（知识库）和 ops-state 卷
docker compose down -v       # 连同数据一起清掉，下次 up 从零开始（场景包会重新自动导入）
```

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| `up` 时报 `required variable OPS_TOKEN is missing a value` | `.env` 里 `OPS_TOKEN` 被删空了，填任意一串随机字符 |
| 引导卡一直显示「等待导入：…（还没有配置模型）」 | `.env` 里 `LLM_API_KEY` 没填，或改完 `.env` 没有重建容器（`docker compose up -d`，`restart` 不重读 env） |
| 引导卡显示「等待工具上线：holiday_calendar、date_info…」 | `kb-ops` 还没起来或起不来：`docker compose logs kb-ops`；确认 `OPS_URL=http://kb-ops:8799`、`COMPOSE_PROFILES=demo` |
| 引导卡显示「休假管理制度.md 入库失败：向量化失败」 | key 无效或余额为 0；到「管理 → 模型设置」点「测试连接」看具体报错。修好后会自动重试 |
| 演示二的两个工具提示「宿主机没有配置 OPS_SECRET_GATEWAY_URL」 | 模型是在页面上填的，没写进 `.env`。页面上填的凭据不会传给工具容器（这是既定边界）；把地址和 key 写进 `.env` 再 `docker compose up -d` |
| `gateway_balance` 返回 404 | 不是硅基流动的端点，没有 `/v1/user/info`；Agent 会说明，去厂商控制台看余额即可。想换接口，改 `packs/model-selfcheck/tools.yaml` 后 `docker compose restart kb-ops` |
| 演示二没有出现 💡 卡片 | 看回答是否真的调了 2 个不同工具、是否有结论；一天最多提 `SOP_PROPOSALS_PER_DAY` 条；同样路径「忽略」过 30 天内不再提；`docker compose logs kb-app` 里有 `no SOP proposal for …: 原因` |
| 每个值都不对 / 密码登不进 | `.env` 带了 `\r`（CRLF）或 BOM，用编辑器改成 LF 后重建容器 |
| 8765 端口被占 | 改 `.env` 的 `PORT`，并把 compose 里的 `127.0.0.1:8765:8765` 同步改掉 |
