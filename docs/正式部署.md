# 正式部署：宿主机 host 网络 + `deploy/release.sh`

一键演示（`docker compose up`）是给陌生人五分钟跑通用的单机形态。正式用时推荐这份文档的形态：
应用容器跑在 **host 网络**，工具服务 `deploy/ops_readonly.py` 以 systemd 跑在宿主机上、只监听 `127.0.0.1`，
模型网关（LiteLLM）或到网关的 SSH 隧道同样只绑 `127.0.0.1`——容器用 host 网络才能直接访问它们，所以这条路径**不走 compose**，
用 `deploy/release.sh` 构建、切换、校验、回滚。

| | 一键演示（compose） | 正式部署（本文） |
|---|---|---|
| 网络 | bridge；应用发布到 `127.0.0.1:APP_PORT`，工具是 sidecar 容器 | host；应用监听 `PORT`（默认 8765），工具和网关都在宿主机 `127.0.0.1` 上 |
| 构建 | `docker compose up --build`，依赖每次走构建缓存 | 依赖预烘焙成 `kb-app:base-<哈希>`，发版只 COPY 代码，几秒钟 |
| 切换 | compose 重建容器 | 停旧 → 起新 → 等就绪 → **比对片段总数** → 不一致自动回滚 |
| 工具 | 来自场景包，`OPS_URL=http://kb-ops:8799` | 宿主机 `ops_readonly.py`，`OPS_URL=http://127.0.0.1:8799`，`include` 场景包的 tools.yaml |
| 配置文件 | 仓库目录里的 `.env` | 任意位置，例如 `/opt/kb-app/.env`，用 `ENV_FILE=` 指给脚本 |

两种形态跑的是同一份代码和同一个 `Dockerfile`（compose 构建它的末尾 `app` 阶段，发版脚本单独用 `base` 阶段）。

## 宿主机布局（推荐）

```
/opt/doc2sop/                 代码：git clone，升级就是 git pull；脚本、文档、场景包都在这里
/opt/kb-app/.env              应用配置（含密钥，0600）；容器的 --env-file
/opt/kb-app/data/             知识库数据：向量库、SQLite、原件；挂到容器 /data
/opt/kb-app/backups/          每日备份包（deploy/backup.sh）
/opt/ops/ops_readonly.py      工具服务（deploy/ 下同名文件的拷贝）
/opt/ops/ops_tools.yaml       工具定义的唯一真相源；旁路文件 overrides / pending / trust / mcp 在同目录
/opt/ops/mcp/                 可选：MCP server（如 holiday_mcp.py）
/etc/ops-readonly.env         工具服务的环境：OPS_TOKEN、OPS_SECRET_*、KUBECONFIG（0600）
```

目录名随意，脚本全部参数化；下面的命令按这个布局写。

## 首次安装

```bash
git clone https://github.com/wangyd1988/doc2sop.git /opt/doc2sop
mkdir -p /opt/kb-app/data && cp /opt/doc2sop/.env.example /opt/kb-app/.env && chmod 600 /opt/kb-app/.env
# 编辑 /opt/kb-app/.env：WEB_PASSWORD、模型地址与 key；COMPOSE_PROFILES 留空；
# OPS_URL=http://127.0.0.1:8799、OPS_TOKEN 与下面 /etc/ops-readonly.env 里的一致。文件保持 LF、无 BOM。
```

工具服务（systemd，模板见 [`deploy/ops-readonly.service.example`](../deploy/ops-readonly.service.example)）：

```bash
mkdir -p /opt/ops && cp /opt/doc2sop/deploy/ops_readonly.py /opt/doc2sop/deploy/ops_tools.yaml /opt/ops/
printf 'OPS_TOKEN=%s\n' "$(openssl rand -hex 24)" > /etc/ops-readonly.env && chmod 600 /etc/ops-readonly.env
# 需要「模型网关」组工具就再加 OPS_SECRET_GATEWAY_URL / OPS_SECRET_GATEWAY_KEY；K8s 工具加 KUBECONFIG
cp /opt/doc2sop/deploy/ops-readonly.service.example /etc/systemd/system/ops-readonly.service   # 核对 ExecStart 里的路径
systemctl daemon-reload && systemctl enable --now ops-readonly
curl -s -H "X-Ops-Token: $(sed -n 's/^OPS_TOKEN=//p' /etc/ops-readonly.env)" http://127.0.0.1:8799/health
```

要用场景包的工具，在 `/opt/ops/ops_tools.yaml` 顶层加一行 `include: [/opt/doc2sop/packs/leave-planning/tools.yaml]`，改完即时生效。

发版（第一次会先构建依赖镜像，2 核机器约 10 分钟；之后每次只 COPY 代码）：

```bash
cd /opt/doc2sop
ENV_FILE=/opt/kb-app/.env DATA_DIR=/opt/kb-app/data bash deploy/release.sh
```

国内网络：Docker Hub 不通就 `BASE_IMAGE=docker.m.daocloud.io/library/python:3.12-slim`，PyPI 慢就
`PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple`——两者都可以写进 `/opt/kb-app/.env`（脚本会读），也可以当环境变量传。

脚本结束会打印运行中的镜像、切换前后片段数和回滚命令。核对：

```bash
docker ps --filter name=kb-app --format '{{.Names}} {{.Image}} {{.Status}}'
curl -s -u admin:'密码' http://127.0.0.1:8765/api/tools | head -c 300     # 列出宿主机工具
```

## 脚本参数

`bash deploy/release.sh --help` 有全文。要点：

| 变量 / 选项 | 含义 | 默认 |
|---|---|---|
| `ENV_FILE` | 容器的 `--env-file`，也从这里读 `PORT`、`WEB_USER`、`WEB_PASSWORD` 和下面的 `APP_*` | `<仓库>/.env` |
| `DATA_DIR` | 挂到容器 `/data` | `<仓库>/data` |
| `APP_CONTAINER` | 容器名；container-guard、监控引用的就是它 | `kb-app` |
| `APP_IMAGE` | 镜像名；冒号前作为仓库名，时间戳 tag 与 `base-<哈希>` 都打在它上 | `kb-app:latest` |
| `APP_MEM_LIMIT` / `APP_CPUS` | `--memory` / `--cpus` | `900m` / `1.5` |
| `APP_PORT` | 探活端口；host 网络下等于 `.env` 的 `PORT` | `.env` 的 `PORT`，再默认 8765 |
| `BASE_IMAGE` / `PIP_INDEX_URL` | 构建依赖镜像用的基础镜像 / pip 源 | `python:3.12-slim` / 官方源 |
| `KEEP_IMAGES` / `START_TIMEOUT` | 保留几个时间戳镜像 / 等新容器就绪多少秒 | `2` / `120` |
| `--image kb-app:<tag>` | 不构建，直接切到一个已有镜像（回滚） | |
| `--rebuild-base` | 强制重建依赖镜像 | |
| `--backup` | 切换前先跑 `deploy/backup.sh`（备份目录 `BACKUP_DIR`，默认 `<DATA_DIR 上级>/backups`） | |
| `--print-config` | 只打印解析后的配置，不碰 docker | |

优先级：环境变量 > `ENV_FILE` 里的同名键 > 默认值。密钥只从环境文件读进内存，探活用的 Basic 凭据经 curl 的 stdin 配置传入，不进命令行，也不打印。
默认值适合「在仓库 clone 目录里直接跑」：`bash deploy/release.sh` 就用 `./.env` 和 `./data`。在仓库任意路径下调用都行，脚本按自己的位置找仓库根。

## 升级

```bash
cd /opt/doc2sop && git pull && ENV_FILE=/opt/kb-app/.env DATA_DIR=/opt/kb-app/data bash deploy/release.sh
```

把 `ENV_FILE`、`DATA_DIR` 写进 `/opt/kb-app/.env`？不行——它们决定去哪儿找这个文件；但 `APP_*`、`BASE_IMAGE`、`PIP_INDEX_URL` 可以写在里面，命令就短成 `ENV_FILE=/opt/kb-app/.env DATA_DIR=/opt/kb-app/data bash deploy/release.sh`。

脚本做的事和失败时的行为：

1. `requirements.txt`、`Dockerfile` 的 base 阶段、`BASE_IMAGE`、`PIP_INDEX_URL` 一起算哈希；`kb-app:base-<哈希>` 不存在才 `docker build --target base`。
2. 用 [`deploy/Dockerfile.release`](../deploy/Dockerfile.release) 在 base 上只 COPY `app/` `packs/`，打 `kb-app:<yyyymmddHHMMSS>`，带 `doc2sop.commit` 标签（`docker inspect` 能看到跑的是哪个提交）。
3. 记下当前片段总数（`/api/documents`）→ `docker stop -t 60` → 改名为 `kb-app-prev` → `docker run -d --network host --env-file … -v DATA_DIR:/data --memory --cpus`。
4. 等 `/api/documents` 返回 200（最多 `START_TIMEOUT` 秒）→ 再读片段总数 → **和切换前不一致、起不来或超时：打印新容器最后 40 行日志，删掉它，把 `kb-app-prev` 改回 `kb-app` 并启动**，退出码 1。
5. 成功：删 `kb-app-prev`，只保留最近 `KEEP_IMAGES` 个时间戳镜像和当前 base，打印回滚命令。

中断约 30–60 秒（停旧容器 + 新容器加载向量库）。如果发现 `kb-app-prev` 残留（上次发版中途被杀），脚本会拒绝开始并给出两条收尾命令。

ops 服务不在镜像里，升级它要单独做（改了 `deploy/ops_readonly.py` 的版本才需要）：

```bash
cmp /opt/doc2sop/deploy/ops_readonly.py /opt/ops/ops_readonly.py || {
  cp -a /opt/ops/ops_readonly.py "/opt/ops/ops_readonly.py.bak-$(date +%Y%m%d%H%M%S)"
  cp /opt/doc2sop/deploy/ops_readonly.py /opt/ops/ && systemctl restart ops-readonly
  sleep 2 && curl -s -H "X-Ops-Token: $(sed -n 's/^OPS_TOKEN=//p' /etc/ops-readonly.env)" http://127.0.0.1:8799/health
}
```

`/health` 返回的工具数应与升级前一致；`/opt/ops/ops_tools.yaml` 是你的配置，升级不会动它。

**场景包和工具服务要一起升级。** 场景包的 `tools.yaml` 会用到工具服务新支持的写法（比如 `impl: {type: builtin}`）。
如果 `/opt/ops/ops_tools.yaml` 直接 include 了 `/opt/doc2sop/packs/...`，`git pull` 之后旧版工具服务会热加载到新写法的条目，
把它们当坏条目跳过（日志里有原因），直到按上面的命令换上新的 `ops_readonly.py`。所以 `git pull` 之后紧接着升级工具服务。

## 回滚

```bash
docker images kb-app --format '{{.Repository}}:{{.Tag}} {{.CreatedAt}}'     # 看还有哪些时间戳镜像
ENV_FILE=/opt/kb-app/.env DATA_DIR=/opt/kb-app/data bash deploy/release.sh --image kb-app:20261024195031
```

同一套切换与校验流程，只是不构建。数据目录在容器外，回滚代码不影响知识库；
如果新版本改过数据格式而需要回到老数据，用备份包恢复（见下）。

## 备份

[`deploy/backup.sh`](../deploy/backup.sh)：SQLite（会话、SOP、图谱、Agent 记忆、对外接入的令牌与审计）在线一致性复制 + 向量库 + 原件 + `/opt/ops/ops_tools*.yaml` 打成一个 tgz，保留最近 7 份。

```bash
echo '30 3 * * * root KB_DATA=/opt/kb-app/data bash /opt/doc2sop/deploy/backup.sh /opt/kb-app/backups >> /var/log/kb-backup.log 2>&1' > /etc/cron.d/kb-backup
KB_DATA=/opt/kb-app/data bash /opt/doc2sop/deploy/backup.sh /opt/kb-app/backups      # 手动跑一次确认产出
```

恢复：`docker stop kb-app` → 把包里的 `data/` 解到 `/opt/kb-app/data`（`ops/` 下的工具配置按需放回 `/opt/ops`）→ `docker start kb-app`。

## 内存看护（可选）

2 GB 的机器上应用容器长时间运行后内存会缓慢爬升。[`deploy/container-guard.sh`](../deploy/container-guard.sh) 只在用量超过阈值时重启容器，配一个 systemd timer 每天凌晨跑一次：

```ini
# /etc/systemd/system/container-guard.service
[Unit]
Description=Restart kb-app when its memory creeps up
After=docker.service
Requires=docker.service
[Service]
Type=oneshot
ExecStart=/opt/doc2sop/deploy/container-guard.sh kb-app 600

# /etc/systemd/system/container-guard.timer
[Unit]
Description=Daily memory check for kb-app
[Timer]
OnCalendar=*-*-* 04:50:00
Persistent=true
RandomizedDelaySec=120
[Install]
WantedBy=timers.target
```

`systemctl enable --now container-guard.timer`。它引用的是容器名，所以发版脚本的 `APP_CONTAINER` 要和这里一致。

## 对外接入（MCP）

让同事的 Claude Code、GitHub Copilot、Cursor 接进来查知识库、按 SOP 排查（能开放什么、令牌、审计见
[`工具.md` 的「对外 MCP 出口」](工具.md#对外-mcp-出口让-claude-codecopilotcursor-用上知识库和-sop)）。默认关，打开分三步：

1. **打开出口**：`/opt/kb-app/.env` 里 `MCP_ENABLED=true`，照常发版。验证：
   `curl -s -o /dev/null -w '%{http_code}\n' -X POST http://127.0.0.1:8765/mcp` 返回 401（关着时是 404）。
2. **签发令牌**：管理页 →「对外接入」→ 签发，每个客户端一枚；明文只显示一次，页面同时给出 Claude Code、VS Code、Cursor 的配置片段。
   要开放数据工具，先在 `/opt/ops/ops_tools.yaml` 里标 `export`（见上面链接），工具服务热加载，不用重启。
3. **网络**：应用直接在 `0.0.0.0:PORT` 上跑明文 HTTP，令牌和返回内容都是明文。按使用范围选一种：
   - **只在本机或经 SSH 隧道用**（最省事，不暴露端口）：`ssh -N -L 8765:127.0.0.1:8765 用户@宿主机`，客户端连 `http://127.0.0.1:8765/mcp`。
   - **对内网开放：前面放反向代理和 TLS**，应用端口只对代理开放。`/mcp` 用 SSE 推流，代理要关缓冲、放长读超时，并单独限流：

```nginx
limit_req_zone $binary_remote_addr zone=mcp:10m rate=5r/s;
server {
    listen 443 ssl;
    server_name kb.example.com;
    ssl_certificate     /etc/ssl/kb.example.com.pem;
    ssl_certificate_key /etc/ssl/kb.example.com.key;
    location /mcp {
        limit_req zone=mcp burst=20 nodelay;
        proxy_pass http://127.0.0.1:8765;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_buffering off;              # SSE：事件要立刻推给客户端
        proxy_read_timeout 3600s;         # 2025 版客户端的通知流是长连接
    }
    location / { proxy_pass http://127.0.0.1:8765; proxy_set_header Host $host; }
}
```

   代理后面想再加一道，就在 `.env` 里设 `MCP_ALLOWED_HOSTS=kb.example.com`：Host 头不在名单里的请求一律 421。
   客户端连 `https://kb.example.com/mcp`。

令牌丢了就在页面上吊销重签（库里只存哈希，找不回明文）。吊销后下一个请求就失败；2025 版客户端已经打开的通知流只推「列表变了」、
不带数据，闲置 30 分钟后关闭。

## 和演示形态并存

同一台机器上可以再跑一套 compose 演示站（比如给人看最新 main）：在另一个目录 clone，那份 `.env` 里设
`APP_CONTAINER=demo-app OPS_CONTAINER=demo-ops APP_IMAGE=demo-app:latest OPS_IMAGE=demo-ops:latest APP_PORT=8766 APP_MEM_LIMIT=700m`，
`LLM_BASE_URL` 指向宿主机上的网关时写 `http://host.docker.internal:14000/v1`（compose 里两个服务都带了 `host.docker.internal`），然后 `docker compose --profile demo up -d --build`。
容器名、镜像名、网络、卷互不干扰；正式站继续由 `release.sh` 管。

## 常见问题

| 现象 | 处理 |
|---|---|
| 第一次发版很慢 | 在构建 `kb-app:base-<哈希>`，2 核机器约 10 分钟；只发生在首次和 `requirements.txt` / base 阶段变化时。构建在切换之前，服务不中断 |
| `docker build` 拉不到 `python:3.12-slim` | 设 `BASE_IMAGE=docker.m.daocloud.io/library/python:3.12-slim`（本地已有该镜像则不会去拉） |
| pip 卡住 | 设 `PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple`；换源会改变哈希，重建一次 base |
| 脚本说「片段总数不一致」并回滚了 | 新版本启动后向量库读不到或读到的和之前不一样——看它打印的新容器日志；常见原因是 `DATA_DIR` 指错、`.env` 里换了 `EMBED_MODEL`（换向量模型会触发重建索引） |
| 脚本说已存在 `kb-app-prev` | 上次发版中途被打断。当前 `kb-app` 正常就 `docker rm -f kb-app-prev`；想回到旧的就 `docker rm -f kb-app && docker rename kb-app-prev kb-app && docker start kb-app` |
| 想看生产跑的是哪个提交 | `docker inspect kb-app --format '{{index .Config.Labels "doc2sop.commit"}}'` |
